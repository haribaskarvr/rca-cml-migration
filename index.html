A controlled path

Export. Review. Apply.

Move the CML and its related constraint associations and context binding, while keeping target changes behind an explicit decision.

01

Export the source

Capture a selected definition version as UTF-8 CML with a checksummed manifest in a unique run folder.

02

Preflight the target

Validate model state, context, catalog matching, associations, and permissions before any target writes.

03

Apply by choice

Review the plan, then pass --apply. Production writes also require --allow-production.

The command surface

One plugin. Three commands.

Choose a task to see its starting command. Replace the uppercase placeholders with your org aliases and model details.

Export a source model and a specific definition version.

sf cml export --source-org SOURCE_ORG_ALIAS --model-api CML_API_NAME --source-version SOURCE_DEFINITION_VERSION_ID_OR_NUMBER --output-dir migration/CML_API_NAME

Preflight an existing export. This command is dry-run by default.

sf cml import --target-org TARGET_ORG_ALIAS --input-dir migration/CML_API_NAME/RUN_FOLDER --dry-run

Export from source, then preflight the target in one invocation.

sf cml migrate --source-org SOURCE_ORG_ALIAS --target-org TARGET_ORG_ALIAS --model-api CML_API_NAME --source-version SOURCE_DEFINITION_VERSION_ID_OR_NUMBER --output-dir migration/CML_API_NAME --dry-run

Built around review

Writes stay deliberate.

Dry-run reports are local artifacts. A successful preflight is not permission to skip review.

01

Dry-run first

Import and migrate validate the target without writing. Apply is a separate, explicit action.

02

Production opt-in

Production writes require the additional --allow-production flag.

03

Recoverable records

Apply runs keep a target backup and action journal, then verify target state after writes. Activation remains separate.

A focused migration, not a catalog deployment.

The target catalog records and context definition must already exist. This tool does not convert BRE rules, migrate catalog metadata, clone version history, or activate models. Review the full project guide for matching rules, authentication, CI setup, and recovery detail.
